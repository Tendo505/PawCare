# Part I — Web, HTTP, REST, and JSON Foundations

## Chapter 1 — The big picture

PawCare has three separate layers:

```text
Android app or Postman
        |
        | HTTP request containing JSON and, when required, a Bearer token
        v
Laravel API
  route -> middleware -> controller -> validation -> model
        |
        | SQL generated by Eloquent
        v
PostgreSQL
```

- Postman and the Android app are **API clients**.
- Laravel receives HTTP requests, applies business and security rules, and returns HTTP responses.
- PostgreSQL stores durable data.
- Clients must never connect directly to PostgreSQL or contain the database password.

The PostgreSQL password belongs only in `backend/.env`. A PawCare user's password belongs in a register or login request. They are unrelated.

## Chapter 2 — What REST means

REST organizes an API around **resources**, which are nouns such as pets, appointments, and medical records. The HTTP method describes the action.

| Purpose | HTTP method | Example | Typical result |
|---|---|---|---|
| List resources | `GET` | `/api/pets` | Array of pets |
| Read one resource | `GET` | `/api/pets/1` | Pet with ID 1 |
| Create a resource | `POST` | `/api/pets` | Newly created pet |
| Replace/update a resource | `PUT` | `/api/pets/1` | Updated pet |
| Partially update a resource | `PATCH` | `/api/pets/1` | Updated pet |
| Delete a resource | `DELETE` | `/api/pets/1` | Empty response |

Do not put action words into resource URLs:

```text
Wrong:   PUT /api/pets/update
Correct: PUT /api/pets/1

Wrong:   DELETE /api/delete-pet/1
Correct: DELETE /api/pets/1
```

`1` is the resource ID. Obtain it from a previous `GET` or `POST` response.

### REST properties worth knowing

- **Stateless:** every protected request supplies its token; the server does not rely on Postman remembering a session.
- **Resource-oriented:** URLs identify nouns; methods describe operations.
- **Consistent:** every PawCare CRUD resource follows the same URL pattern.
- **Representational:** JSON is the representation sent between client and server.
- **Idempotent:** repeating a properly designed `GET`, `PUT`, or `DELETE` should normally have the same final effect. Repeating `POST` may create duplicates.

## Chapter 3 — JSON fundamentals

JSON contains objects, arrays, strings, numbers, booleans, and `null`.

```json
{
  "name": "Buddy",
  "species": "Dog",
  "weight_kg": 28.4,
  "vaccinated": true,
  "notes": null,
  "tags": ["friendly", "active"]
}
```

Rules:

- Property names and strings use double quotes.
- Do not add a comma after the final property.
- Numbers and booleans should not be quoted.
- JSON comments are not allowed.
- Dates should use a stable format such as `YYYY-MM-DD`.
- Time in PawCare appointments uses `HH:mm`, for example `10:30`.

JSON is not the correct format for every request. PawCare's AI image endpoint uses `multipart/form-data` because it uploads a file.

## Chapter 4 — Anatomy of an HTTP request

Every request has four important parts:

```text
METHOD + URL
Headers
Optional request body
Optional query parameters
```

Example:

```http
PUT /api/pets/1 HTTP/1.1
Host: pawcare-api.test
Accept: application/json
Content-Type: application/json
Authorization: Bearer 1|plain-text-token

{
  "name": "Buddy",
  "species": "Dog",
  "breed": "Labrador",
  "sex": "Male"
}
```

### Headers used by PawCare

| Header | Meaning |
|---|---|
| `Accept: application/json` | Ask Laravel to return JSON, including for errors. |
| `Content-Type: application/json` | Tell Laravel that the request body is JSON. |
| `Authorization: Bearer <token>` | Authenticate a protected request. |

`GET` and `DELETE` usually do not need a body or `Content-Type`. They should still send `Accept` and, if protected, `Authorization`.

## Chapter 5 — HTTP status codes

The status code is the first thing to inspect in Postman.

| Code | Meaning in this API |
|---|---|
| `200 OK` | Successful login, list, read, or update. |
| `201 Created` | Successful registration or resource creation. |
| `204 No Content` | Successful deletion; an empty body is correct. |
| `400 Bad Request` | Malformed request. |
| `401 Unauthenticated` | Missing, invalid, or old token. |
| `403 Forbidden` | Authenticated but not allowed to perform the action. |
| `404 Not Found` | Route or owned resource not found. PawCare also returns 404 when a record belongs to another user. |
| `405 Method Not Allowed` | URL exists, but the selected HTTP method is wrong. |
| `422 Unprocessable Content` | JSON reached Laravel but failed validation. |
| `429 Too Many Requests` | Rate limit exceeded. |
| `500 Internal Server Error` | Unhandled backend exception; inspect `backend/storage/logs/laravel.log`. |
| `503 Service Unavailable` | PawCare's breed-recognition service is unavailable. |

Never treat every non-200 response as the same problem. Read both the status and JSON body.

## Chapter 6 — PawCare route map

Laravel automatically adds the `/api` prefix to routes in `backend/routes/api.php`.

### Public authentication routes

| Method | URL | Purpose |
|---|---|---|
| `POST` | `/api/register` | Create a user and return a token. |
| `POST` | `/api/login` | Verify credentials and return a token. |

These routes cannot require a token because their purpose is to issue the token.

### Protected account routes

| Method | URL | Purpose |
|---|---|---|
| `GET` | `/api/me` | Return the authenticated user. |
| `POST` | `/api/logout` | Delete the current token. |
| `GET` | `/api/dashboard` | Return dashboard counts and upcoming items. |

### Protected CRUD routes

The following pattern exists for `pets`, `vaccinations`, `medical-records`, and `appointments`:

| Method | Pattern | Controller operation |
|---|---|---|
| `GET` | `/api/{resource}` | `index` — list records |
| `POST` | `/api/{resource}` | `store` — create record |
| `GET` | `/api/{resource}/{id}` | `show` — read one record |
| `PUT` or `PATCH` | `/api/{resource}/{id}` | `update` — update record |
| `DELETE` | `/api/{resource}/{id}` | `destroy` — delete record |

Examples:

```text
GET    /api/pets
POST   /api/pets
GET    /api/pets/1
PUT    /api/pets/1
DELETE /api/pets/1

GET    /api/vaccinations
PUT    /api/vaccinations/4

GET    /api/medical-records
DELETE /api/medical-records/2

GET    /api/appointments
PATCH  /api/appointments/3
```

### AI prediction routes

| Method | URL | Purpose |
|---|---|---|
| `GET` | `/api/ai-predictions` | Return paginated prediction history. |
| `POST` | `/api/ai-predictions` | Upload an image for prediction. |

See the authoritative list at any time:

# Part II — Authentication and Hands-On API Workflows

## Chapter 7 — Authentication with Laravel Sanctum

PawCare uses Laravel Sanctum personal access tokens.

### Register

```http
POST http://pawcare-api.test/api/register
```

```json
{
  "name": "Test Owner",
  "email": "owner@example.com",
  "password": "password123"
}
```

Successful response: `201 Created`.

### Login

```http
POST http://pawcare-api.test/api/login
```

```json
{
  "email": "demo@pawcare.my",
  "password": "PawCare123"
}
```

Example response:

```json
{
  "token": "1|long-plain-text-token",
  "user": {
    "id": 1,
    "name": "Aina Rahman",
    "email": "demo@pawcare.my"
  }
}
```

Copy only the token value. Do not include quotes or type `Bearer` inside Postman's Bearer Token field; Postman adds that word automatically.

### Important PawCare token behavior

`AuthController@login` runs:

```php
$user->tokens()->delete();
```

Therefore, every new login invalidates all older tokens for that user. Always use the token from the most recent login. This is why a previously working collection can suddenly return `401` after another login.

Sanctum stores only a hash of the token in `personal_access_tokens`. The plaintext token is available only in the register/login response and cannot be recovered from pgAdmin.

### Protected request

```http
GET http://pawcare-api.test/api/me
Accept: application/json
Authorization: Bearer 1|long-plain-text-token
```

### Logout

```http
POST http://pawcare-api.test/api/logout
Accept: application/json
Authorization: Bearer 1|long-plain-text-token
```

After logout, that token cannot be used again.

## Chapter 9 — Complete pet workflow

### List pets

```http
GET {{base_url}}/api/pets
```

No body. Use inherited Bearer authentication and `Accept: application/json`.

### Create a pet

```http
POST {{base_url}}/api/pets
```

```json
{
  "name": "Milo",
  "species": "Cat",
  "breed": "Siamese",
  "sex": "Male",
  "birth_date": "2024-01-15",
  "weight_kg": 4.2,
  "microchip_number": null,
  "notes": "Indoor cat"
}
```

Allowed pet values and constraints:

- `name`: required, maximum 100 characters.
- `species`: required; exactly `Dog` or `Cat`.
- `sex`: required; exactly `Male`, `Female`, or `Unknown`.
- `birth_date`: optional; cannot be in the future.
- `weight_kg`: optional number from 0 through 300.
- `pet_breed_id`: optional ID that must exist in `pet_breeds`.
- `age` is not accepted; send `birth_date`.

### Read one pet

```http
GET {{base_url}}/api/pets/{{pet_id}}
```

This response also loads that pet's vaccinations, medical records, appointments, images, and predictions.

### Update a pet

```http
PUT {{base_url}}/api/pets/{{pet_id}}
```

```json
{
  "name": "Milo",
  "species": "Cat",
  "breed": "British Shorthair",
  "sex": "Male",
  "birth_date": "2024-01-15",
  "weight_kg": 4.8,
  "notes": "Updated weight"
}
```

Although the route accepts `PATCH`, the current controller uses `required` validation rules for `name`, `species`, and `sex`. In this project, send the complete required payload for both `PUT` and `PATCH` unless the validation rules are changed to use `sometimes`.

### Delete a pet

```http
DELETE {{base_url}}/api/pets/{{pet_id}}
```

Success is `204 No Content`. An empty response is expected.

## Chapter 10 — JSON bodies for other PawCare resources

Every create request below uses `POST /api/{resource}`. Every update uses `PUT /api/{resource}/{id}` and currently expects all required fields.

### Vaccination record

```json
{
  "pet_id": 1,
  "vaccination_id": null,
  "vaccine_name": "Rabies Booster",
  "administered_date": "2026-07-20",
  "due_date": "2027-07-20",
  "clinic": "Happy Tails Veterinary",
  "status": "Completed",
  "notes": "No adverse reaction"
}
```

`status` must be `Upcoming`, `Completed`, or `Overdue`. The `pet_id` must belong to the authenticated user.

### Medical record

```json
{
  "pet_id": 1,
  "veterinarian_id": null,
  "visit_date": "2026-07-20",
  "veterinarian": "Dr. Lim Wei",
  "diagnosis": "Mild dermatitis",
  "treatment": "Medicated shampoo for 14 days",
  "notes": "Follow up if symptoms return"
}
```

`visit_date` cannot be in the future.

### Appointment

```json
{
  "pet_id": 1,
  "veterinarian_id": null,
  "appointment_date": "2026-08-15",
  "appointment_time": "10:30",
  "clinic": "Happy Tails Veterinary",
  "reason": "Annual wellness examination",
  "status": "Scheduled",
  "notes": "Bring vaccination card"
}
```

`status` must be `Scheduled`, `Completed`, or `Cancelled`. Time must be in 24-hour `HH:mm` format.

### AI prediction image upload

Do not use raw JSON.

```http
POST {{base_url}}/api/ai-predictions
```

In Postman choose **Body → form-data**:

| Key | Type | Value |
|---|---|---|
| `image` | File | Select a JPG/PNG image, maximum 10 MB. |
| `pet_id` | Text | Optional owned pet ID. |

Laravel forwards the image to `AI_SERVICE_URL/predict`. A `503` means the separate AI service is unavailable, not that PostgreSQL is broken.

## Chapter 12 — Request lifecycle in PawCare

For `PUT /api/pets/1`, Laravel roughly performs these steps:

1. Nginx/Herd sends the request to `public/index.php`.
2. Laravel matches `PUT api/pets/{pet}`.
3. `auth:sanctum` reads and verifies the Bearer token.
4. Route model binding loads `Pet` ID 1.
5. `PetController@update` checks that the pet belongs to the authenticated user.
6. Laravel validates the JSON.
7. Eloquent updates PostgreSQL.
8. Laravel serializes the fresh model as JSON and returns `200`.

Knowing the stage helps debugging:

- `404/405` often means route or method.
- `401` means middleware/token.
- `422` means validation.
- Database exception means configuration, schema, constraint, or query.
- `500` requires the log and stack trace.

## Chapter 13 — Routes and resource controllers

PawCare uses:

```php
Route::middleware('auth:sanctum')->group(function () {
    Route::apiResource('pets', PetController::class);
});
```

`apiResource` generates five operations: `index`, `store`, `show`, `update`, and `destroy`. It omits the HTML `create` and `edit` routes because JSON clients do not need server-rendered forms.

Conceptual controller:

```php
class PetController extends Controller
{
    public function index(Request $request): JsonResponse
    {
        return response()->json($request->user()->pets()->get());
    }

    public function store(Request $request): JsonResponse
    {
        $data = $request->validate([
            'name' => ['required', 'string'],
            'species' => ['required', 'in:Dog,Cat'],
        ]);

        $pet = $request->user()->pets()->create($data);

        return response()->json($pet, 201);
    }
}
```

Routes decide **where and with which method**. Controllers decide **what happens**.

## Chapter 14 — Validation

Never trust JSON from a client. Validate before writing it to the database.

```php
$data = $request->validate([
    'name' => ['required', 'string', 'max:100'],
    'species' => ['required', 'in:Dog,Cat'],
    'weight_kg' => ['nullable', 'numeric', 'min:0', 'max:300'],
]);
```

With `Accept: application/json`, invalid input produces `422`:

```json
{
  "message": "The species field must be one of Dog or Cat.",
  "errors": {
    "species": [
      "The species field must be one of Dog or Cat."
    ]
  }
}
```

For larger controllers, generate a Form Request:

```powershell
php artisan make:request StorePetRequest
```

Then place validation and request-specific authorization in that class. This keeps controllers short and makes create/update rules easier to maintain.

### `PUT` versus `PATCH`

- `PUT` normally sends the full representation.
- `PATCH` normally sends only changed fields.

To support a true partial patch, optional update rules commonly use `sometimes`:

```php
'name' => ['sometimes', 'required', 'string', 'max:100'],
```

The current PawCare controllers reuse full validation for both methods, so they require all required fields.

## Chapter 15 — Eloquent models

Eloquent maps PHP model objects to database rows.

```php
$pet = Pet::findOrFail(1);
$pet->weight_kg = 29.1;
$pet->save();
```

### Mass assignment

PawCare models declare `$fillable`:

```php
protected $fillable = [
    'user_id',
    'name',
    'species',
    'breed',
    'sex',
    'birth_date',
    'weight_kg',
];
```

Only allowed fields are mass assignable through `create()` and `update()`. Still validate input; `$fillable` is not validation.

### Hidden and cast values

The User model hides password fields from JSON:

```php
protected $hidden = ['password', 'remember_token'];
```

Its `password` cast hashes assigned passwords. Pet casts convert `birth_date` and format `weight_kg`.

## Chapter 16 — Eloquent relationships and ownership

PawCare relationships include:

```text
User has many Pets
User has many Appointments
Pet belongs to User
Pet has many VaccinationRecords
Pet has many MedicalRecords
Pet has many Appointments
Pet has many AiPredictions
```

Examples:

```php
$pets = $request->user()->pets()->get();
$owner = $pet->user;
$records = $pet->medicalRecords;
```

Use eager loading to avoid the N+1 query problem:

```php
$pets = $request->user()
    ->pets()
    ->with('petBreed')
    ->get();
```

### Authentication is not authorization

- **Authentication:** who is the caller?
- **Authorization:** may this caller access this record?

PawCare verifies ownership before showing, updating, or deleting records:

```php
abort_unless($pet->user_id === $request->user()->id, 404);
```

This prevents User A from changing User B's pet by guessing an ID. For a larger application, move these rules into Laravel policies.

## Chapter 17 — Route model binding

This route:

```text
PUT /api/pets/7
```

matches `{pet}`. Because the controller parameter is `Pet $pet`, Laravel automatically finds Pet ID 7:

```php
public function update(Request $request, Pet $pet)
```

If no record exists, Laravel returns 404. Route model binding removes repetitive `Pet::findOrFail($id)` code.

## Chapter 18 — Migrations, seeders, and PostgreSQL

### Migrations

Migrations are version-controlled schema changes. They create and alter tables, columns, indexes, and foreign keys.

```powershell
php artisan migrate:status
php artisan migrate
```

Create a migration:

```powershell
php artisan make:migration add_colour_to_pets_table --table=pets
```

Do not manually change production table structure in pgAdmin and forget to create a migration. Other environments and teammates need the same repeatable schema history.

### Seeders

Seeders create known development data:

```powershell
php artisan db:seed
php artisan migrate --seed
```

PawCare's seeder creates:

- Demo user `demo@pawcare.my` with application password `PawCare123`.
- Buddy and Luna.
- Breeds, vaccination types, records, and an appointment.

The demo password is not the PostgreSQL password.

### Local database configuration

PawCare's current PostgreSQL 18 instance uses port 5432:

```env
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=pawcare
DB_USERNAME=postgres
DB_PASSWORD='your-postgresql-password'
```

After changing `.env`:

```powershell
php artisan config:clear
php artisan migrate:status
```

If `migrate:status` succeeds, Laravel—not merely pgAdmin—can reach the database.

### Transactions

Use a transaction when several writes must all succeed or all fail:

```php
DB::transaction(function () use ($data) {
    $appointment = Appointment::create($data);
    Notification::create([/* ... */]);
});
```

## Chapter 19 — JSON responses and API Resources

Simple response:

```php
return response()->json($pet);
```

Created response:

```php
return response()->json($pet, 201);
```

Delete response:

```php
return response()->json(null, 204);
```

For a stable public response format, use an API Resource:

```powershell
php artisan make:resource PetResource
```

```php
class PetResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'species' => $this->species,
            'breed' => $this->breed,
            'age' => $this->birth_date?->age,
        ];
    }
}
```

Resources prevent accidental API changes when database columns change and let you control nested relationships.

## Chapter 20 — Pagination, filtering, sorting, and versioning

Large collections should not return every row:

```php
$pets = $request->user()->pets()->paginate(20);
```

Typical query parameters:

```text
GET /api/pets?page=2
GET /api/pets?species=Dog
GET /api/appointments?status=Scheduled
GET /api/medical-records?sort=-visit_date
```

Validate allowed filters and sort fields; never insert arbitrary client strings directly into SQL.

If the API will have multiple incompatible public versions, introduce a prefix such as `/api/v1`. Do not create a new version for every small additive change.

## Chapter 21 — Error handling and debugging

Use this order:

1. Confirm method and URL with `php artisan route:list --path=api`.
2. Confirm `Accept: application/json`.
3. Confirm a fresh Bearer token for protected routes.
4. Inspect the response status and JSON.
5. Run `php artisan migrate:status` for database connectivity.
6. Inspect `backend/storage/logs/laravel.log` for a real 500.

Useful commands:

```powershell
php artisan route:list --path=api
php artisan config:clear
php artisan cache:clear
php artisan migrate:status
Get-Content .\storage\logs\laravel.log -Tail 100
```

### Why a missing token previously produced a 500

Without `Accept: application/json`, Laravel treated the unauthenticated request like a browser request and attempted to redirect to a named `login` web route. PawCare has only `POST /api/login`, not a named web login route, so the redirect raised `Route [login] not defined`.

Every API request should send `Accept: application/json`. For a stronger server-side guarantee, configure Laravel's exception rendering so requests under `api/*` always render JSON.

Conceptual `bootstrap/app.php` configuration:

```php
use IlluminateFoundationConfigurationExceptions;
use IlluminateHttpRequest;
use Throwable;

->withExceptions(function (Exceptions $exceptions): void {
    $exceptions->shouldRenderJsonWhen(
        fn (Request $request, Throwable $e) =>
            $request->is('api/*') || $request->expectsJson()
    );
})
```

In production, set `APP_DEBUG=false` so stack traces and environment details are not returned to clients.

## Chapter 22 — Testing Laravel APIs

Feature tests exercise routes, middleware, controllers, models, and the database together.

PawCare already includes an authentication test and a create/list pet test.

```php
public function test_user_can_create_and_list_own_pet(): void

    $this->postJson('/api/pets', [

        'species' => 'Cat',
        'breed' => 'Siamese',
        'sex' => 'Male',
        'birth_date' => '2024-01-15',
        'weight_kg' => 4.2,
    ])->assertCreated();

    $this->getJson('/api/pets')
        ->assertOk()
        ->assertJsonCount(1)
        ->assertJsonPath('0.name', 'Milo');
}
```

Run tests:

```powershell
php artisan test
php artisan test --filter=AuthAndPetTest
```

Important cases to add:

- Missing token returns 401 JSON.
- Invalid JSON returns validation errors.
- User cannot read/update/delete another user's records.
- Creating each resource returns 201.
- Updating returns 200 and persists fields.
- Deleting returns 204.
- Login invalidates older tokens if that is intentional.
- AI service failure returns 503.

Tests are the permanent proof of behavior; Postman is excellent for exploration but is not a substitute for automated tests.

## Chapter 23 — Security checklist

- Never put `DB_PASSWORD` in Kotlin, JavaScript, Postman examples, Git, or an APK.
- Never return password hashes or token hashes in JSON.
- Use HTTPS outside local development.
- Validate every client-controlled field.
- Scope database queries to the authenticated user.
- Use policies for complex authorization.
- Use rate limits for login, registration, and expensive AI endpoints.
- Keep `.env` private and rotate secrets that leak.
- Give database applications a limited database user instead of a PostgreSQL superuser in production.
- Restrict uploaded image MIME types, sizes, storage access, and filenames.
- Do not expose `APP_DEBUG=true` publicly.
- Log errors server-side without logging passwords, tokens, or private medical data.

## Chapter 24 — Connecting the Android app

Android should call Laravel through an HTTP client such as Retrofit:

```kotlin
interface PawCareApi {
    @POST("api/login")
    suspend fun login(@Body request: LoginRequest): AuthResponse

    @GET("api/pets")
    suspend fun pets(@Header("Authorization") authorization: String): List<PetDto>
}
```

A production-style OkHttp interceptor can add the token and JSON header to protected requests:

```kotlin
class AuthInterceptor(private val tokenStore: TokenStore) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val request = chain.request().newBuilder()
            .header("Accept", "application/json")
            .apply {
                tokenStore.token()?.let { header("Authorization", "Bearer $it") }
            }
            .build()

        return chain.proceed(request)
    }
}
```

Do not ship the demo credentials as permanent production authentication. Do not connect Android directly to PostgreSQL.

`pawcare-api.test` is a hostname configured on the Windows development machine. An Android emulator may not resolve it automatically. The emulator normally reaches the host machine through `10.0.2.2`, so local mobile testing may require a reachable host URL/port or a local DNS/network configuration. Production must use an HTTPS domain.

## Chapter 25 — Common misconceptions

### “pgAdmin is connected, so Laravel is connected”

Not necessarily. pgAdmin and Laravel are separate PostgreSQL clients with separate host, port, username, and password settings. `php artisan migrate:status` proves Laravel connectivity.

### “The demo password is the database password”

No. `PawCare123` authenticates a row in the `users` table. PostgreSQL credentials authenticate Laravel itself to the database server.

### “I can copy the token from pgAdmin”

No. Sanctum stores a token hash. Copy the plaintext token from the latest register/login response.

### “POST, PUT, and DELETE need different URLs such as `/create` and `/update`”

No. They normally share the same resource URL and differ by HTTP method. Update/delete also include the record ID.

### “A 500 means my JSON is wrong”

Usually invalid fields produce 422. A 500 means an unhandled server exception. Inspect `laravel.log`.

# Part VI — Advanced to Professional Laravel Engineering

The earlier chapters teach the complete foundation. The remaining chapters develop the architecture, performance, reliability, security, testing, and operational judgment expected from senior and lead engineers.

## Chapter 29 — Professional application architecture

CRUD controllers are an excellent starting point. As rules grow, keep controllers focused on HTTP concerns and move domain behavior into dedicated classes.

```text
Route
  -> Middleware
  -> Form Request (authorization + validation)
  -> Controller (HTTP orchestration)
  -> Action/Service (use case)
  -> Eloquent models/repositories
  -> API Resource (response contract)
```

A professional controller can be thin:

```php
final class UpdatePetController
{
    public function __invoke(
        UpdatePetRequest $request,
        Pet $pet,
        UpdatePet $action,
    ): PetResource {
        Gate::authorize('update', $pet);

        return new PetResource(
            $action->handle($pet, $request->validated())
        );
    }
}
```

The action owns the use case:

```php
final class UpdatePet
{
    public function handle(Pet $pet, array $data): Pet
    {
        $pet->update($data);

        return $pet->refresh();
    }
}
```

This separation becomes useful when the same operation is called from HTTP, an Artisan command, a scheduled task, or a queue job.

### Introduce abstractions for a reason

| Abstraction | Appropriate use |
|---|---|
| Form Request | Validation or request authorization is no longer trivial. |
| Policy | Ownership/role checks repeat across methods. |
| API Resource | Clients need a stable response contract. |
| Action/Service | A use case coordinates several models or external services. |
| DTO | Typed data must cross layers without loose arrays. |
| Repository | Persistence must genuinely be replaceable, or complex queries need an explicit boundary. Do not wrap every Eloquent call automatically. |
| Event + listener | Other work should react without coupling to the main use case. |
| Queue job | Work is slow and need not finish before the HTTP response. |

Avoid “architecture by folder count.” Add a boundary because it protects a real responsibility.

### Dependency inversion

Depend on a contract when multiple implementations or isolated testing justify it:

```php
interface BreedPredictor
{
    public function predict(UploadedFile $image): PredictionResult;
}
```

Bind the production HTTP implementation in a service provider and use a fake implementation in a focused test. Keep framework code near the edge and domain rules testable without HTTP.

### Modular architecture

As PawCare grows, organize by domain capability rather than putting hundreds of unrelated classes into generic folders:

```text
app/
├── Pets/
│   ├── Actions/
│   ├── Data/
│   ├── Events/
│   ├── Policies/
│   └── Resources/
├── Appointments/
├── Vaccinations/
└── BreedRecognition/
```

A module should own cohesive behavior and expose deliberate interfaces. Do not split into microservices merely because modules exist.

## Chapter 30 — Professional authorization and token design

Replace repeated ownership checks with policies:

```powershell
php artisan make:policy PetPolicy --model=Pet
```

```php
final class PetPolicy
{
    public function view(User $user, Pet $pet): bool
    {
        return $pet->user_id === $user->id;
    }

    public function update(User $user, Pet $pet): bool
    {
        return $pet->user_id === $user->id;
    }

    public function delete(User $user, Pet $pet): bool
    {
        return $pet->user_id === $user->id;
    }
}
```

Controller:

```php
Gate::authorize('update', $pet);
```

Use 403 when revealing the resource is acceptable. Return 404 when hiding whether another user's record exists is a deliberate security requirement.

### Sanctum abilities

Issue limited tokens:

```php
$token = $user->createToken('android', ['pets:read', 'pets:write']);
```

Check an ability:

```php
abort_unless($request->user()->tokenCan('pets:write'), 403);
```

A production token policy should define:

- Device/token naming.
- Minimum required abilities.
- Expiration and rotation.
- Revocation and logout behavior.
- Lost-device handling.
- Audit history.
- Whether login on one device invalidates other devices.

PawCare currently deletes all older tokens at every login. That is simple and secure for a one-device model, but it prevents simultaneous sessions.

### Rate limiting

Protect login and expensive endpoints. A conceptual per-email/IP limiter:

```php
RateLimiter::for('login', function (Request $request) {
    $key = Str::lower((string) $request->input('email')).'|'.$request->ip();

    return Limit::perMinute(5)->by($key);
});
```

Attach it with `throttle:login`. A limited client receives 429. Combine rate limiting with monitoring and, where appropriate, progressive delay or account-protection controls.

### Authentication threat model

Consider token theft, brute force, credential stuffing, compromised devices, leaked logs, replay, database theft, and privilege escalation. HTTPS protects tokens in transit. Hashing protects stored passwords and Sanctum tokens at rest. Authorization still must protect each owned resource.

## Chapter 31 — Advanced REST and contract design

### Stable envelopes

Choose a consistent success format:

```json
{
  "data": {
    "id": 1,
    "name": "Buddy"
  },
  "meta": {
    "request_id": "01J..."
  }
}
```

Use a stable error shape:

```json
{
  "message": "Validation failed.",
  "code": "VALIDATION_FAILED",
  "errors": {
    "species": ["The selected species is invalid."]
  },
  "request_id": "01J..."
}
```

Machine-readable error codes should remain stable even if human messages change.

### Backward compatibility

Usually safe:

- Adding an optional response field.
- Adding an endpoint.
- Adding an optional request field.

Usually breaking:

- Renaming/removing a field.
- Changing a field's type or meaning.
- Making an optional input required.
- Changing a relied-upon status code.

Version incompatible contracts deliberately, for example `/api/v1`, and maintain a documented deprecation window.

### Idempotency

Mobile clients retry after timeouts. The first POST may have succeeded even if the response was lost. For duplicate-sensitive operations:

1. Accept an `Idempotency-Key` header.
2. Uniquely store key + authenticated user + endpoint.
3. Execute the operation once in a transaction.
4. Persist the result/status.
5. Return the same result for repeated keys.

Enforce uniqueness in PostgreSQL. An application-only “check then insert” has a race condition.

### Optimistic concurrency

Two clients may edit the same pet. Send a version or `updated_at`, then update only if it still matches. Return 409 or 412 when the server record changed so the client refreshes rather than silently overwriting another edit.

HTTP-native alternatives use `ETag`, `If-None-Match`, and `If-Match` for caching and concurrency.

### Filtering and sorting

Use a predictable, allowlisted convention:

```text
GET /api/pets?filter[species]=Dog&sort=-created_at&page=2
GET /api/appointments?include=pet&filter[status]=Scheduled
```

Validate allowed filters, includes, and sorts. Cap page sizes. Never put unchecked client column names into a query.

### OpenAPI

Maintain an OpenAPI specification for paths, authentication, parameters, request schemas, responses, and errors. A contract can generate documentation, clients, mocks, and compatibility checks.

## Chapter 32 — Advanced PostgreSQL and Eloquent performance

Correctness comes first. Optimize measured bottlenecks.

### Indexes

Indexes should support common filtering, joins, and ordering. Potential PawCare indexes include:

```php
$table->index(['user_id', 'name']);
$table->index(['user_id', 'appointment_date', 'status']);
$table->index(['pet_id', 'due_date', 'status']);
```

Each index consumes storage and slows writes. Verify the query pattern first.

Inspect a PostgreSQL plan:

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM appointments
WHERE user_id = 1 AND status = 'Scheduled'
ORDER BY appointment_date;
```

Look for sequential scans, index scans, poor row estimates, expensive sorts, and repeated nested loops. `EXPLAIN ANALYZE` executes the query, so use it carefully on modifying or expensive statements.

### N+1 queries

Bad:

```php
$appointments = Appointment::all();
foreach ($appointments as $appointment) {
    echo $appointment->pet->name;
}
```

Better:

```php
$appointments = Appointment::with('pet:id,name')->get();
```

In local/testing environments, prevent unexpected lazy loading so N+1 problems fail visibly.

### Pagination choices

- `paginate()` provides total counts but may run an expensive count query.
- `simplePaginate()` skips the total count.
- `cursorPaginate()` scales well for large ordered datasets and avoids offset drift.

Cursor pagination needs stable, unique, indexed ordering.

### Large datasets

Do not load millions of models into memory:

```php
Pet::query()->chunkById(500, function ($pets) {
    // Process a bounded batch.
});
```

Use `cursor()` or lazy collections when appropriate. For bulk writes, consider set-based SQL rather than one model save per row.

### Transactions and locks

For invariants under concurrency:

```php
DB::transaction(function () use ($appointmentId) {
    $appointment = Appointment::query()
        ->lockForUpdate()
        ->findOrFail($appointmentId);

    // Re-check invariants, then update.
});
```

Keep transactions short. Do not call a slow AI service while holding database locks.

### Constraints

Application validation gives good errors. PostgreSQL constraints guarantee integrity under concurrency. Use foreign keys, unique indexes, `NOT NULL`, and checks where appropriate.

## Chapter 33 — Queues, events, cache, and external systems

### Events and listeners

Publish a domain event after a meaningful change:

```php
PetVaccinationRecorded::dispatch($record);
```

Listeners can schedule a reminder, write an audit record, and send a notification without crowding the controller. Events describe what happened; jobs describe work to perform.

### Queue slow work

Good queue candidates:

- Emails and push notifications.
- Report generation.
- Image processing.
- Retryable AI calls.

```powershell
php artisan make:job ProcessBreedPrediction
php artisan queue:work
```

Jobs must be retry-safe. Configure timeout, tries, exponential backoff, failed-job handling, and monitoring. Do not assume exactly-once execution.

### Cache read-heavy results

```php
$dashboard = Cache::remember(
    "dashboard:user:{$user->id}",
    now()->addMinutes(5),
    fn () => $this->buildDashboard($user),
);
```

Caching creates an invalidation responsibility. Invalidate/version the key when relevant pets, appointments, vaccinations, or medical records change. Never cache private data under a key that omits user/tenant identity.

### Resilient AI service calls

```php
$response = Http::acceptJson()
    ->connectTimeout(3)
    ->timeout(15)
    ->retry(3, 250)
    ->attach(/* image */)
    ->post($url);
```

Design for connection failure, timeout, non-2xx status, invalid JSON, overload, and retries that repeat work. Validate the service response before indexing fields. Mock the boundary with `Http::fake()`.

### File storage

Use Laravel Storage rather than hard-coded paths. Production files often live in object storage. Store searchable metadata in PostgreSQL and the binary object in the configured disk. Validate MIME type, extension, size, image dimensions, and access policy.

## Chapter 34 — Observability, debugging, and operations

Advanced engineering includes proving what production is doing.

### Structured logging

```php
Log::info('pet.updated', [
    'user_id' => $request->user()->id,
    'pet_id' => $pet->id,
    'request_id' => $request->header('X-Request-ID'),
]);
```

Never log Bearer tokens, passwords, database credentials, or unnecessary medical data.

### Request correlation

Generate or accept a request ID, include it in logs and responses, and propagate it to the AI service and queue jobs. One ID should trace a request across Android, Laravel, PostgreSQL-related work, queues, and external services.

### Metrics

Measure:

- Request rate, latency percentiles, and errors by route.
- 401, 422, 429, 500, and 503 counts.
- PostgreSQL query latency and slow queries.
- Queue depth, job duration, retries, and failures.
- Cache hit rate.
- AI service latency, timeout, and error rate.

Averages hide slow outliers; use percentiles such as p50, p95, and p99.

### Health checks

Separate shallow liveness from readiness. A PHP process can be alive while unable to reach PostgreSQL or the queue. Avoid an expensive public endpoint that itself becomes a load source.

### Audit trail

For sensitive changes, record actor, action, resource, timestamp, and safe before/after details. Ordinary application logs are not automatically a tamper-resistant audit system.

### Incident method

1. State user impact and time window.
2. Check recent deploy/config/schema changes.
3. Use request IDs, metrics, and logs to locate the failing boundary.
4. Mitigate safely before pursuing the perfect fix.
5. Preserve evidence.
6. Verify recovery with user-level signals.
7. Write follow-up actions that address causes, detection, and recovery.

## Chapter 35 — Advanced automated testing

Use several levels:

| Test type | Purpose |
|---|---|
| Unit | Pure domain rule or value-object behavior. |
| Feature | Full Laravel request through middleware, controller, and test database. |
| Integration | PostgreSQL, filesystem, cache, queue, or external adapter behavior. |
| Contract | Compatibility with Android or OpenAPI. |
| End-to-end | Critical flow through a deployed system. |

Test more than the happy path:

- Missing, invalid, revoked, expired, or underprivileged tokens.
- Another user's resource.
- Every validation boundary.
- Foreign-key/unique constraint failure.
- Duplicate submission and retries.
- Concurrent updates.
- External timeout, failure, and malformed JSON.
- Stable pagination and ordering.
- Response schema and hidden fields.

Use factories to create only required state. `RefreshDatabase` isolates tests. Tests must not depend on execution order or the development seeder.

Use Laravel fakes for HTTP, queue, events, notifications, mail, time, and storage when testing another concern. Keep separate integration tests for real adapters.

### CI quality gates

A mature pipeline runs:

```text
Dependency installation
Formatting/lint check
Static analysis
Unit and feature tests
Migration verification
Security/dependency audit
Build/package verification
```

Treat flaky tests as defects. A test suite nobody trusts provides little protection.

## Chapter 36 — Security engineering

Apply defense in depth:

- HTTPS everywhere outside local development.
- Strict validation and output encoding.
- Policies and least privilege.
- Restricted database role in production.
- Rate limits on auth and expensive routes.
- Secret storage outside source control.
- Safe upload handling.
- Dependency patching and audits.
- `APP_DEBUG=false` in production.
- Token revocation, rotation, and monitoring.
- Backups protected like production data.

### Threat-model PawCare

Assets include credentials, tokens, pet medical data, uploaded images, model predictions, and availability. Boundaries include Android-to-API, API-to-PostgreSQL, API-to-storage, API-to-AI service, and queue workers.

For each boundary ask:

- Who can call it?
- How is identity established?
- Which data is accepted and returned?
- Can requests be replayed or duplicated?
- What happens when it is slow or unavailable?
- What is logged?
- How are secrets rotated?

### Multi-tenancy

If PawCare later serves clinics, every tenant-owned table/query/cache key/job/storage path must include and enforce tenant identity. Relying on developers to remember `where tenant_id = ?` everywhere is fragile; establish central scopes/policies and test cross-tenant isolation aggressively.

## Chapter 37 — Production deployment and scaling

Production differs from local Herd/Postman development.

### Production principles

- Serve only Laravel's `public/` directory.
- Use HTTPS.
- Set `APP_ENV=production` and `APP_DEBUG=false`.
- Inject secrets through the deployment platform.
- Use a restricted PostgreSQL role.
- Back up PostgreSQL and test restoration.
- Supervise queue workers and restart them on deploy.
- Monitor errors, latency, queues, and storage.

Common optimization commands:

```powershell
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

Rebuild caches after environment or route changes.

### Safe schema evolution

Use expand-and-contract changes:

1. Add new schema in a backward-compatible form.
2. Deploy code that writes both old/new forms when necessary.
3. Backfill large data in batches.
4. Switch readers.
5. Stop writing the old form.
6. Remove old schema only after all instances are compatible.

Plan locks, index creation, rollback, and mixed-version application instances.

### Horizontal scaling

With several Laravel instances:

- Do not rely on local process memory for shared state.
- Use shared cache/queue infrastructure as needed.
- Store uploads on shared/object storage.
- Centralize logs and metrics.
- Make requests and jobs concurrency-safe.
- Gracefully restart workers so old code does not process new job formats forever.

### Disaster recovery

Define recovery point objective (acceptable data loss) and recovery time objective (acceptable downtime). Automate backups, encrypt them, store copies separately, monitor failures, and perform restoration drills. An untested backup is only a hope.
